# PR 리뷰 검토 (Codex)

PR을 올리면 Codex(`chatgpt-codex-connector[bot]`)가 리뷰를 단다. 리뷰는 몇 분 뒤에 달린다.
**PR 생성 → 리뷰 대기 → 검토안 제시**까지 사용자에게 묻지 않고 진행한다. 사용자는 검토안만 보고, 반영할 항목을 고른다.

## 1. 대기 시작 (PR 생성·푸시 직후, 같은 응답에서)

- 새 PR을 만든 직후: `bash .claude/skills/pr-review/scripts/wait-codex-review.sh <PR번호>`
- 이미 열린 PR에 커밋을 더 푸시한 직후: `bash .claude/skills/pr-review/scripts/wait-codex-review.sh <PR번호> --trigger`
  - Codex는 새 커밋에 자동으로 다시 리뷰하지 않으므로 `@codex review` 댓글로 요청한다.
- 반드시 Bash의 `run_in_background: true`로 실행한다. 폴링하거나 sleep으로 기다리지 않는다. 스크립트가 끝나면 알림이 온다.
- 사용자에게는 "Codex 리뷰를 기다리는 중이고, 끝나면 검토안을 올리겠다"고 한 줄만 알린다.

스크립트 동작:
- 1분마다 Codex 요약 댓글의 상태 표시(`codex-review-state:v1`)를 확인한다. PR의 현재 head 커밋에 대해 `status=completed`가 되면 끝난다.
- 10분 동안 리뷰가 시작되지 않으면 `@codex review` 댓글을 한 번 단다.
- 40분이 지나면 `TIMEOUT`을 출력하고 종료 코드 2로 끝난다.
- 완료되면 head 커밋에 대한 리뷰 본문과 인라인 지적(파일:줄, 본문)을 출력한다.

## 2. 검토 (알림이 오면)

- `TIMEOUT`이면 사용자에게 알리고 다시 기다릴지 묻는다.
- `has_findings=false`이고 인라인 지적이 없으면 "지적 없음"이라고 짧게 알린다.
- 지적이 있으면 지적마다:
  1. 지적한 파일과 주변 코드, 관련 호출부를 직접 읽는다. Codex 설명만 보고 판단하지 않는다.
  2. 실제로 일어나는 문제인지 판단한다. 스펙(`docs/`), 스킬 규칙, 운영 조건(MySQL 설정, 데이터 형식 등)과 대조한다.
  3. 중요도를 매긴다. Codex의 P0~P3 배지는 참고만 하고, 아래 기준으로 직접 정한다.
  4. 고칠 방법과 영향 범위(코드, DDL, 테스트)를 정한다. 테스트로 재현할 수 있으면 어떤 테스트를 추가할지도 적는다.

중요도 기준:

| 중요도 | 기준 | 처리 |
| --- | --- | --- |
| 상 | 데이터 손실·잘못된 적재, Job 실패나 장애, 보안·개인정보 문제가 실제로 일어날 수 있다 | 머지 전에 반드시 고친다 |
| 중 | 특정 조건에서만 실패하거나, 성능·운영 위험이 있거나, 규칙과 어긋난다 | 이번 PR에서 고치는 것을 권한다 |
| 하 | 가독성·스타일·개선 제안, 일어날 가능성이 매우 낮다 | 후속 작업으로 미뤄도 된다 |
| 반영 안 함 | 오탐이거나, 이미 정한 설계와 충돌한다 | 근거를 적는다 |

## 3. 검토안 제시

중요도 높은 순으로 아래 형식으로 보여준다. 코드는 아직 고치지 않는다.

```
## Codex 리뷰 검토안 — PR #<번호> (`<커밋 7자리>`)

지적 N건: 상 a · 중 b · 하 c · 반영 안 함 d

### [상] 1. <한 줄 요약>
- 위치: [파일:줄](경로#L줄)
- Codex 지적: <무슨 문제라고 했는지 한두 문장>
- 판단: <실제로 일어나는지, 근거>
- 제안: <고칠 방법, 바뀌는 파일, 추가할 테스트>

### [중] 2. ...

반영할 번호를 알려주세요. (예: "1, 2 반영")
```

## 4. 반영 (사용자가 요청한 항목만)

- 사용자가 고른 항목만 고친다. 고르지 않은 항목은 손대지 않는다.
- 항목마다 테스트와 함께 고치고 커밋한다 (convention 스킬의 커밋 규칙).
- 푸시는 사용자가 요청할 때만 한다. 푸시하면 1번의 `--trigger`로 다시 리뷰를 기다린다.
- GitHub에 답글을 달거나 대화를 resolve하는 것은 사용자가 요청할 때만 한다.
